# Hand-written remarks for the generated scale catalog (see ScaleCatalog / ScaleCatalogTest).
#
# One entry per line:   <key> = <remark>
# The key is the display name a handler reports (the "Scale" column of the generated table). A
# handler class name works too and then covers every product that driver reports.
# Lines starting with '#' are comments. Markdown (links included) is allowed in the remark.
#
# Everything else in the table — display name, connection type, capabilities — comes from the
# handler's supportFor() and must be changed there, not here.

Xiaomi Mi Scale v1 = No data on the scale is ever deleted
Xiaomi Body Composition Scale S400 = See [#1297](https://github.com/oliexdev/openScale/pull/1297) for more details
Wyze Scale (WHSCL1) = Needs the scale's 32-character device key from the Wyze cloud. See [#853](https://github.com/oliexdev/openScale/issues/853)
iHealth HS2S = Untested on hardware, see [#853](https://github.com/oliexdev/openScale/issues/853)
Wyze Scale X = No Wyze account or key needed. The scale keeps using the weight unit openScale is set to. See [#853](https://github.com/oliexdev/openScale/issues/853)
iHealth HS2S Pro = Untested on hardware, see [#853](https://github.com/oliexdev/openScale/issues/853)
Sanitas SBF70 / SilverCrest SBF75 / Crane = The assigned user name on the scale and in openScale have to be the same, see [FAQ](Frequently-Asked-Questions-(FAQ)#how-do-i-get-the-body-metrics-water-muscle-fat-percentage-on-my-sbf70-scale)
Digoo DG-SO38H (Mengii) = Initialisation process needs to be reverse engineered. Currently you have to use the vendor's app once to initialise the scale.
ES-CS20M / ES-32MD = Uses the Trisa Body Analyze body measurement library until the original [QN scale library](https://github.com/oliexdev/openScale/issues/373) is fully reverse engineered
Custom openScale = See [here](Custom-Bluetooth-Scale) for a tutorial
Trisa Body Analyze 4.0 = See [Trisa Body Analyze](Trisa-Body-Analyze) for the protocol
ProfiCare PC-PW 3008 BT = Same Chipsea "WeChat scale" firmware as the Hoffen BBS-8107, so it is driven by the same handler
HuaweiHagridWspHandler = The scale only answers after a Huawei Hagrid handshake, so CAK, C1 and C2 (32 hex characters each) have to be entered in the device settings first
AiLink Body Fat Scale = Non-connectable: the whole measurement is TEA-encrypted inside the advertisement, so no pairing is needed and the vendor "AiLink" app can be removed. Covers the AiLink/eLink broadcast family (advertises service 0xF0A0, often named "EL1")
PICOOC Mini Lite = Tested with the PICOOC-L broadcast protocol. Weight and impedance are recorded, and the adult Caucasian/White body-composition path is a clean-room port of the PICOOC 4.3.0 ARM64 implementation.
PICOOC-CQ = Includes Mini Pro (13-byte measurement frames) and S3 Lite V2.0 (16-byte frames). Weight and impedance are recorded; missing body-composition values are estimated by openScale's StandardImpedanceLib.
QN Scale (Broadcast) = No pairing needed. Tested with the FITINDEX FT-26R-W, which reports weight only (no body composition — these units have no electrodes). Stay on the scale until the display stops changing, around six seconds; it only reports a reading once it settles, so stepping off earlier records nothing.
AAAxHandler = No pairing needed: the Icomon/Fitdays "AAA" boards only broadcast. Weight only; the impedance frame is not decoded. Newer boards (e.g. "AAA07A", Posture FG220LB) are recognised by their advertisement, not just by name.
Fitdays FG2202WB = Body composition needs the handlebar held during the weigh-in; with feet only the scale measures no impedance
Sacoma Ultra = Body composition needs the handlebar held during the weigh-in; with feet only the scale measures no impedance
Qardio QardioBase / QardioBase 2 = Works without the defunct Qardio cloud. openScale stores each app user as a profile on the scale (several phones can share one scale; names are shown lowercase, max 6 characters). Body composition (fat, water, skeletal muscle, bone) is the scale's own and needs a recognised profile; lean body mass and BMI come from openScale. The QardioBase 2 identifies who is on it and learns from the first 1-3 weigh-ins; weigh-ins it assigns to someone else or to guest are not saved (guest saving can be enabled). The scale cannot delete a single user; use the reset in the device settings. Wi-Fi upload, goal and display modes are not used. QardioBase X is a different device and is not supported.
Chipsea-BLE = Chipsea GATT body-fat scale (service 0xFFF0, vendor app "OKOK International") — not the broadcast OKOK protocol
Urikar Aero I = Sold with the Fitdays app (the label reads "Urikar APP"). The display unit (kg, lb, st) follows the weight unit set in openScale. Body composition needs bare feet on the electrodes; without contact only the weight is recorded.
Grifema GA2001 / Senssun IF_B7 = Sold as the Grifema "GA2001 Smart Body Fat scale" (brand printed on the glass, the plate on the back reads "Smart Body Fat scale / Model: GA2001"); it is a Senssun/Camry Broad Fat Scale DC board and advertises as `IF_B7`, which is the name to tap in the scan list. Non-connectable: the reading is carried in the advertisement, so no pairing is needed. Weight and impedance are recorded; body composition comes from openScale's StandardImpedanceLib, not the scale's own algorithm, so it will not match the vendor app. The scale reports an impedance only in its BIA phase, which needs skin contact with the four electrode discs; when it reports none, only the weight is recorded, and openScale's usual value inheritance carries the previous entry's composition numbers into the new one. The weight field jitters by ~1 kg packet to packet, so openScale stores the median of the last readings, which is the number the display settles on. Stay on the scale barefoot for about 30 s: the BIA pass starts ~15 s after stepping on, and stepping off before it finishes stores the weight alone.
